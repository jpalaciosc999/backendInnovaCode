DOCUMENTO DE FUNCIONALIDAD DEL BACKEND
=====================================

Proyecto: backendInnovaCode
Fecha de generacion: 2026-05-30

1. Resumen general
------------------
Este backend es una API REST construida con Node.js, Express y Oracle Database.
Su objetivo principal es administrar procesos de recursos humanos y nomina:
empleados, contratos, asistencia/marcajes, periodos, ingresos, descuentos,
prestamos, KPI, liquidaciones, reportes y seguridad basada en roles/permisos.

El punto de entrada de la aplicacion es src/server.js, que carga variables de
entorno, inicializa el pool de Oracle y levanta el servidor HTTP. La aplicacion
Express se configura en src/app.js.

2. Tecnologias y dependencias
-----------------------------
- Express 5: servidor HTTP y enrutamiento.
- oracledb: conexion y ejecucion de consultas contra Oracle.
- dotenv: carga de variables de entorno.
- cors: control de origenes permitidos.
- jsonwebtoken: autenticacion JWT.
- bcryptjs: validacion y generacion de hashes de contrasenas.
- pdfkit: generacion de reportes PDF.
- nodemon: ejecucion en desarrollo.

Scripts disponibles:
- npm run dev: inicia con nodemon src/server.js.
- npm start: inicia con node src/server.js.

3. Configuracion principal
--------------------------
Archivo: src/app.js
- Habilita CORS para FRONTEND_URL y origenes locales comunes.
- Permite metodos GET, POST, PUT, DELETE y OPTIONS.
- Expone el header Content-Disposition para descargas PDF.
- Usa express.json con limite de 1mb.
- Normaliza respuestas de error para devolver { error } cuando el status es 400+.
- Expone GET / con mensaje de salud: "Backend funcionando correctamente".
- Monta todos los modulos REST.

Archivo: src/server.js
- Carga dotenv.
- Usa PORT desde .env o 4000 por defecto.
- Llama initDB() antes de escuchar peticiones.
- Cierra el pool de Oracle en SIGINT.

Archivo: src/config/db.js
- Crea un pool Oracle con ORACLE_USER, ORACLE_PASSWORD y ORACLE_CONNECT_STRING.
- Configura outFormat como objeto.
- Configura autoCommit por defecto en consultas simples.
- Expone executeQuery(sql, binds, options).
- Expone executeTransaction(callback), con commit al finalizar y rollback ante error.
- Cierra conexiones en finally.

4. Seguridad, autenticacion y permisos
--------------------------------------
Modulos principales:
- src/routes/auth/auth.controller.js
- src/middlewares/auth.middleware.js
- src/utils/adminAccess.js
- src/utils/auditoria.js

Autenticacion:
- POST /auth/login
  Valida username o correo y password contra EMP_USUARIO.
  Soporta contrasenas en texto plano antiguas y hashes bcrypt que empiezan con $2.
  Rechaza usuarios inactivos.
  Devuelve token JWT, expiracion, datos de usuario, rol y permisos.

- POST /auth/readtoken
  Valida un token recibido en body.
  Devuelve usuario decodificado, permisos y datos de expiracion.

Middleware JWT:
- verificarToken exige header Authorization: Bearer <token>.
- requierePermiso(modulo, permiso) valida que el usuario vigente tenga un permiso.
- requiereAlgunoPermiso(...) permite acceso si el usuario posee al menos uno.
- requiereRolVigente valida que usuario y rol sigan activos en base de datos.

Permisos:
- Los permisos se cargan desde EMP_ROL_PERMISOS y EMP_PERMISOS.
- El middleware normaliza texto, acentos, guiones y espacios para comparar permisos.
- Hay alias de modulo: ADMIN, REPORTES, EMPLEADOS, NOMINA y ASISTENCIA.

Auditoria:
- registrarBitacora inserta acciones en EMP_BITACORA.
- Si existe usuario autenticado, relaciona usuario y bitacora en EMP_USUARIO_BITACORA.
- Registra accion, tabla afectada, registro, descripcion, valores anterior/nuevo e IP.

10. Flujo funcional principal
-----------------------------
1. Se crean roles, permisos y usuarios.
2. Un usuario inicia sesion en /auth/login y recibe JWT.
3. Administracion gestiona empleados, puestos, departamentos, sedes, horarios y
   contratos.
4. Se configuran periodos, conceptos de ingresos, descuentos y asignaciones.
5. Los empleados registran marcajes o se ingresan marcajes manuales.
6. Se cargan KPI/resultados, prestamos y descuentos adicionales.
7. Se genera nomina por periodo con /nominas/generar.
8. La nomina calcula ingresos, descuentos, horas extra, KPI, IGSS, ISR y prestamos.
9. Se consultan reportes operativos, fiscales y ejecutivos.
10. Si un empleado termina relacion laboral, se calcula y registra liquidacion.

11. Observaciones importantes
-----------------------------
- No todas las rutas estan protegidas por token en app.js; la proteccion se aplica
  dentro de algunos routers. Modulos administrativos y reportes sensibles si tienen
  middlewares explicitos.
- El backend usa autoCommit en executeQuery, y transacciones explicitas en procesos
  sensibles como nomina, empleados, contratos, roles, permisos, prestamos y
  liquidaciones.
- Varias rutas tienen aliases con mayusculas/minusculas para compatibilidad con el
  frontend.
- Los PDFs se descargan mediante Content-Disposition.
- La aplicacion depende de variables de entorno para Oracle, JWT, expiracion del
  token, puerto y URL del frontend.
- Algunos controladores incluyen funciones CRUD que no necesariamente estan
  expuestas por el router actual.
